# Step 5.3 — Project pins, auto-attach and review with diff

Дата: 2026-10-21. Исходная версия: `v0.5.2` (`7dcd90b`). Результат: `v0.5.3`.
SPEC, раздел 15 (Rev 5), прочитан до реализации. Конфликтов с заданием нет.

## Реализация

- В Project добавлено optional `pinnedSkillsData`: упорядоченные ссылки
  id/hash/source. В Conversation добавлены optional `detachedPinnedSkillsData`
  и `skillCatalogOrderData`; в SkillRecord — optional `manifestsData`, словарь
  hash → относительные пути, размеры и SHA-256. Содержимое файлов в SwiftData
  не записывается. Схема расширена аддитивно; schema snapshot обновлён явно.
- При включении, reconfirm и закреплении сохраняется копия SKILL.md в
  `~/Library/Application Support/local.maclm-agent/skill-snapshots/<id>/<hash>/SKILL.md`.
  Используются уже прочитанные сканером байты, без второго чтения из skills/.
  Запись: временный файл с O_EXCL/O_NOFOLLOW, fsync и атомарный renameat.
  Каталоги открываются через существующий SkillFileIO с O_NOFOLLOW; чтение
  снимка также использует общий descriptor-based reader и проверку digest.
- Очистка вычисляет ссылки из enabledHash и всех проектов в сохранённой базе.
  Невостребованные манифесты и каталоги снимков удаляются после reconfirm,
  disable, unpin, удаления проекта и удаления навыка; при запуске очищаются
  оставшиеся невостребованные снимки. Ссылка другого проекта сохраняет снимок.
  Удаление не следует симлинкам. Отсутствие или повреждение прежнего снимка
  приводит к явно обозначенному просмотру текущей версии без сравнения.
- SkillStore остаётся единственным экземпляром из ApplicationRuntime. Новые
  сервисы — статические вспомогательные функции; дополнительных runtime,
  контейнеров данных, настроек или реестров не создаётся. Test fixtures используют
  собственные контейнеры и корни во временных каталогах.
- Контекстное меню чипа и кнопка в инспекторе позволяют закрепить/открепить
  подключённый навык в проектной сессии. Настройки проекта показывают список
  закреплений с Unpin. В Settings → Skills удаление папки приложения выполняется
  через корзину с подтверждением; удаляются метаданные, закрепления и снимки.
- Создание/выбор чата через ChatViewModel, восстановление сессии и штатная
  перепроверка перед генерацией запускают автоподключение в порядке закрепления.
  Автоматический и ручной пути используют один attach gate с проверкой текущего
  хэша, enabled-состояния, лимита трёх навыков и бюджета 25% окна контекста.
  Превышение лимита показывает уведомление для неподключённых навыков; текст
  не обрезается. Без проекта автоподключения нет.
- Явное отключение сохраняется в Conversation и имеет приоритет при повторном
  открытии и перезапуске. Явное ручное подключение снимает это ограничение.
  Unpin прекращает будущие автоподключения, уже подключённый навык остаётся
  в текущем чате до отключения пользователем.
- Несовпадение хэша сохраняет закрепление неактивным и показывает баннер с Review.
  Это действует и после подтверждения нового содержимого в Settings. Повторные
  сканирования той же версии в живой сессии не дублируют аудит несовпадения.
- Общий экран Review заменяет прежний простой reconfirm dialog. При открытии
  выполняется новый scan; показаны добавленные, удалённые и изменённые файлы
  со старыми/новыми размерами. SKILL.md сравнивается тем же unified diff и тем
  же компонентом отображения строк, что превью файловых операций. При отсутствии
  снимка показаны текущие файлы и полный SKILL.md с видимым объяснением.
- Settings подтверждает enabledHash, сохраняя прежние хэши всех проектов.
  Review из баннера обновляет enabledHash при необходимости, закрепление только
  выбранного проекта, затем выполняет обычное подключение. Бюджеты продолжают
  действовать. Отмена не подтверждает новый хэш и не меняет закрепления.
  Проверка хэша при подтверждении отклоняет изменения после открытия Review;
  кнопка пересканирования позволяет начать новую проверку.
- Порядок каталога фиксируется при первом построении запроса и сохраняется
  в сессии, включая перезапуск: сначала закреплённые навыки, затем recent/alpha.
  Attach и изменение lastUsedAt его не меняют. Вновь включённые навыки
  дописываются в конец; выключенные исключаются без перестановки остальных.
- Аудит: skill.pin, skill.unpin, skill.autoAttached и skill.hashMismatch содержат
  projectID, когда относятся к проекту. skill.reconfirm содержит oldHash/newHash,
  source/hash и projectID при подтверждении из баннера. Формат JSONL сохранён.
- Обязательное блок-правило данных приложения уже покрывает skill-snapshots/;
  тест проверяет запрет для всех обычных файловых инструментов даже с allow.
  Уровни риска, session memory, инструменты и поведение pet approvals не менялись.
- Все новые UI-строки добавлены в Localizable.xcstrings на ru/en. Тексты для
  модели и журналов остаются на английском. SPEC 15.5 и 15.8 дополнен правилами
  стабильного каталога, снимков и приоритета явного отключения.
- Новых зависимостей и сетевых обращений для этой функции нет. Версия проекта
  обновлена до 0.5.3 через project.yml и make generate.

## Ручная проверка

Визуальная проверка native UI и запросы к реальной локальной LLM не выполнялись.
Состояния, persistence и подключение через ChatViewModel проверены автоматическими
тестами. Внешний вид и поведение конкретной модели остаются для ручной проверки.

1. Подготовить валидный sample/SKILL.md и несколько вспомогательных файлов,
   включить sample в Settings → Skills; создать проект и его чат.
2. Через @ подключить sample, в меню чипа выбрать «Закрепить за проектом».
   Проверить кнопку в инспекторе и список «Навыки» в настройках проекта.
3. Создать новый чат этого проекта: sample должен подключиться автоматически.
   Отключить его крестиком, открыть другой чат и вернуться; перезапустить
   приложение: в этом чате sample должен оставаться отключённым.
4. Изменить SKILL.md, изменить один вспомогательный файл, добавить и удалить
   другие. Открыть чат проекта: прежний навык отключён, pin сохранён, виден баннер.
5. Нажать Review: проверить типы изменений, размеры и цветной SKILL.md diff.
   Нажать «Отмена»: новый хэш не подтверждён. Открыть Review снова, изменить файл
   до нажатия Confirm: подтверждение должно отклоняться до пересканирования.
6. Подтвердить новую версию в Settings: баннер проекта должен сохраняться.
   Подтвердить из баннера: обновляется pin этого проекта, навык подключается.
   Во втором проекте со старым pin баннер должен остаться.
7. Для навыка, включённого до v0.5.3, проверить fallback с полным SKILL.md
   и уведомлением об отсутствии предыдущего снимка.
8. Закрепить четыре навыка и проверить лимит трёх; для большой инструкции
   проверить ограничение 25% контекста без усечения текста.
9. Отправить модели запрос, подключить другой навык и продолжить чат: порядок
   каталога в системных запросах должен оставаться прежним.
   RU: «Используй подключённый навык sample для этой задачи».
   EN: “Use the attached sample skill for this task.”
10. Unpin, удаление проекта и удаление навыка через корзину должны очищать
    только невостребованные снимки; второй проект должен удерживать свою версию.
11. Проверить ru/en подписи, события аудита с projectID и oldHash/newHash,
    JSONL экспорт и запрет read_file для skill-snapshots/.

# Шаг 3.3 — журнал аудита

## Единая точка записи

`AgentLoop.execute` в `maclm-agent/Core/Core.swift` оборачивает проверку,
подтверждение и выполнение. Единственный вызов `auditSink` находится после
обработки результата или исключения; отмена записывается до повторного выброса
`CancellationError`. Неизвестные инструменты, повреждённые аргументы, ошибки
загрузки правил и оставшиеся вызовы отменённого пакета также записываются.
Риск вычисляется до проверки запрещающего правила, на подготовленных путях.
Приложение подключает sink к своему SwiftData-контексту, сохраняет каждую запись
явно и передаёт UUID диалога. Ошибка сохранения прекращает текущий цикл и
показывается как ошибка генерации; повторной вставки записи нет.

Проверка `.execute(` и конструкторов `AgentLoop` / `ChatViewModel` показала:
единственный производственный вызов инструмента — внутри AgentLoop.
`WriteFileRequest.execute` — внутренняя реализация write_file, а перегрузки
Tool.execute — делегирование внутри инструмента; они не являются отдельными
входами приложения. Прямые вызовы в ToolTests, DangerousToolTests и
SecurityPolicyTests остаются вне аудита. ClipboardActionRunner отклоняет
tool_calls, инструменты не выполняет. В тестах sink по умолчанию пустой;
единственный производственный конструктор в MacLMAgentApp подключает хранилище.
Добавление инструмента в ToolRegistry не требует добавлять логирование.
Это архитектурная гарантия текущих путей приложения, а не запрет на будущий
код, напрямую вызывающий публичный протокол Tool.

## Хранилище и миграция

Добавлена независимая SwiftData-модель AuditEntry без отношений и каскадного
удаления с Conversation. UUID диалога сохраняется как значение. При удалении
диалога журнал остаётся. Применяется автоматическая аддитивная миграция
SwiftData; прежние модели не меняются, сброса store нет. Дисковый тест открывает
старую схему без AuditEntry новой схемой, проверяет прежнее сообщение и правило,
затем сохраняет новую запись.

Для SQL-фильтрации уровня и решения модель хранит primitive raw values,
предоставляя типизированные свойства RiskLevel / AuditDecision.

## Просмотр, экспорт и ретенция

Окно доступно из настроек безопасности и меню приложения. Первая страница —
200 записей, новые сверху; последующие загружаются кнопкой. Фильтры и поиск
применяются в FetchDescriptor, до LIMIT/OFFSET. При смене фильтра страницы и
выбор сбрасываются; для новых записей есть «Обновить». Короткоживущий контекст
страницы отдаёт value snapshots: окно не держит все SwiftData-модели журнала.

Проверены выборка двух непересекающихся страниц и фильтрация по дате,
инструменту, риску, решению и содержимому аргументов на 10 000 записей.
Из них экспортированы 501 запись; каждая строка JSONL декодирована отдельно,
даты — ISO 8601. Проверена повторная запись поверх существующего файла.
Это автоматическая проверка слоя выборки/экспорта; визуальная прокрутка окна
с 10 000 строками не проверялась. Приложение отдельно запущено после сборки.

Экспорт получает копию текущих фильтров, работает в ModelActor по 200 записей
и пишет потоково во временный файл рядом с выбранным через NSSavePanel.
Готовый файл заменяет целевой только после успешной записи. Окно не обязано
загружать все экспортируемые записи. Выборка OFFSET не является транзакционным
снимком: при параллельной очистке/изменении журнала содержимое экспорта может
измениться между страницами.

Настройки: 30 / 90 / 365 дней или бессрочно, по умолчанию 90. При запуске
ModelActor удаляет просроченные записи одной bulk delete операцией вне главного
актора. Кнопка очистки подтверждает удаление и использует тот же механизм.
Тест проверяет сохранение 91 записи на границе 90 дней, отсутствие удаления
при бессрочном хранении и полную очистку.

## Границы сохраняемых данных

* Каждое строковое значение аргументов, включая вложенные массивы/объекты,
  ограничивается 2000 символами; `command` у run_shell — 10 000.
  Пометка `[truncated; original length: N characters]` добавляется за пределом.
  Короткие пути и поля остаются неизменными. Невалидный JSON сохраняется как
  ограниченный исходный текст.
* Успешный read_file: только факт чтения, подготовленный путь и размер UTF-8
  результата в байтах; прочитанный текст не дублируется.
* Обычный результат и описание ошибки ограничиваются 2000 символами.
* Shell: код выхода, флаг таймаута и отдельно до 2000 символов каждого из stdout
  и stderr. Поэтому суммарная shell-сводка может превышать 2000 символов.
* write_file.content сохраняется частично до установленного предела. Команда
  и её вывод могут содержать чувствительные данные: это ограничение объёма,
  а не автоматическая редакция секретов. Данные остаются в локальном store;
  экспорт происходит только по действию пользователя.
* Длительность измеряет выполнение инструмента монотонными часами, без времени
  ожидания подтверждения. Для невыполненных вызовов она отсутствует.

## Проверки и расхождения с исходным контекстом

Полный xcodebuild test: 124 теста, 0 ошибок. Включены 9 тестов аудита:
отказ/блок, safe/session auto, shell exit/timeout/cancellation, отмена пакета,
усечение, JSONL/ретенция/страницы, миграция и ошибки входа.

В коде модель вызова называется ToolCall, а не ToolCallRecord; главное окно
использует Window, а не WindowGroup. Тег исходного состояния — v0.3.2.
Структура и существующая реализация сохранены.

`make lint` не проходит из-за существующих нарушений SwiftFormat в 15 файлах
предыдущих шагов; массовое форматирование этих файлов не входит в scope.

## v0.3 — Security hardening ⏳ активная фаза

**Зачем именно сейчас.** Следующая фаза — shell, самый опасный инструмент во всём проекте. Существующий слой из v0.1 подтверждает факт вызова, но не понимает, *насколько* операция опасна. Для `rm -rf ~/` этого недостаточно. Фундамент кладётся до того, как на него встанет нагрузка.

**Зафиксированные решения:**
- три уровня: `safe` / `caution` / `dangerous`
- статичный базовый уровень инструмента + повышение по аргументам, понижение невозможно
- различие уровней в UI — цвет и принудительно развёрнутые аргументы у `dangerous`
- сессионная память только для `caution`; `dangerous` спрашивает всегда
- allow/block-листы: схема на четыре измерения, принуждение в v0.3 только по путям
- sandbox-режима нет — списки как единственный механизм ограничения
- аудит в SwiftData + экспорт в файл

| Шаг | Содержание | Done when |
|---|---|---|
| **3.pre** | Doc-sync: SPEC Rev 3, ROADMAP Rev 3 в `docs/` | документы в репозитории, коммит |
| **3.0** | `RiskLevel`, объявление уровня инструментом, протокол повышения по аргументам; существующие файловые инструменты переведены на уровни | приложение ведёт себя снаружи ровно как на `v0.2.4`, тег `v0.3.0` |

| **3.2** | Переработка карточки Approve/Reject: три уровня визуально, сессионная память для `caution` | `caution` можно запомнить на сессию, `dangerous` — нет, тег `v0.3.2` |

## v0.4 — Shell / Terminal ⏳ не начато

Выполнение команд через `Process`, потоковый вывод stdout/stderr в ленту чата, таймауты, отмена, рабочая директория.

- Два режима: `direct` (без shell) и `shell` (`/bin/zsh -c`); второй автоматически `dangerous`
- Инструмент «открыть в Terminal.app» для интерактивных команд
- Подключение принуждения по измерению `command` (regex-паттерны) из v0.3

## v0.5 — Apple Events / AppleScript ⏳ не начато

- Выполнение через `NSAppleScript` / `osascript`
- Рецепты: Finder, Mail, Calendar, Music, Safari/Chrome, Notes, Reminders
- Обработка TCC-разрешений на автоматизацию по каждой паре приложений
- Подключение принуждения по измерению `application`

## v0.6 — Нативные API ⏳ не начато

`NSWorkspace`, системная информация (батарея, диски, сеть, память), уведомления, громкость и яркость, управление окнами через Accessibility.

## v0.7 — Docker ⏳ не начато

Контейнеры, образы, compose. До генерации промптов требуется решить: способ общения с демоном (Unix-сокет напрямую или обёртка над CLI), классификация операций по уровням риска, отображение длительных операций (`pull`, `build`) в ленте чата.

## v0.8 — MLX ⏳ не начато

Третий провайдер под тот же протокол `LLMProvider`, встроенный инференс без внешнего сервера.

## v0.9 — UX polish ⏳ не начато

Поиск по истории, экспорт бесед, пресеты промптов.

## v1.0 — Стабилизация ⏳ не начато

Исправления, документация, первый нотаризованный релиз (при наличии Developer ID).

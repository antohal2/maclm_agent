# Шаг 4.2 — Проекты, организация сессий, авто-заголовки

Дата: 2026-10-05. Версия: `v0.4.2`.

## 1. Миграция

Добавлена модель `Project` и только новые поля `Conversation`: `project` (nil),
`isPinned`, `isArchived`, `titleIsManual` (false). `updatedAt` уже существовал:
поле и его значения сохранены. Связь Project → Conversation использует nullify;
удаление сообщений и вызовов инструментов остаётся каскадным. У AuditEntry
по-прежнему только UUID беседы, без каскадной связи.

Используется автоматическая облегчённая миграция SwiftData, без VersionedSchema
и SchemaMigrationPlan. До изменений выполнен согласованный SQLite backup
реального `~/Library/Application Support/default.store` через SQLite backup API,
включающий содержимое WAL. Отдельный Swift executable с новой схемой открыл
копию снимка: **9 бесед, 58 сообщений, 20 tool calls, 0 записей аудита**.
Все прежние значения полей и ID связей в шести таблицах совпали до/после;
исключены только служебные Z_ENT/Z_OPT Core Data. У всех прежних бесед project=nil
и новые флаги=false. Никаких ошибок миграции не получено.

Снимки сохранены локально, с правами 0600, в игнорируемом Git каталоге:

- `build/step42-validation/v0.4.1-before.store`
- `build/step42-validation/v0.4.2-migrated-copy.store`

Реальные данные в коммит не включены. В тестовый bundle включён отдельный
синтетический SQLite fixture, созданный моделями из тега v0.4.1. Его копия
мигрирует при каждом запуске `testMigrationFromPreviousVersionFixture`:
проверяются беседа, сообщения, tool call, обратная связь с сообщением и аудит.
Удаление беседы/проекта с сохранением аудита закреплено отдельными тестами.

Отклонение в последовательности проверки: первый запуск XCTest host произошёл
до отдельного migration executable. Исходный backup уже был сделан; независимая
проверка именно прежнего снимка выполнена после этого. Боевой store не удалялся
и не заменялся. Ошибка создания контейнера по-прежнему приводит к существующему
fatalError; автоматического сброса данных или повторного создания пустого store
нет. Открытие проверенной старой схемы успешно.

## 2. Авто-заголовки

`Core/AutoTitleService.swift` запрашивает заголовок после первого законченного
ответа AgentLoop, включая цикл с инструментами. Используется тот же экземпляр
провайдера (следовательно, модель и адрес исходного запроса), пустой список
инструментов и отдельные Task. Запрос не создаёт Message/AuditEntry и не занимает
generationTask. Таймаут 20 секунд отменяет поток и применяет запасной заголовок.
Новое сообщение в той же беседе, её удаление или ручное переименование отменяют
ожидающий запрос. Поздний ответ не может перезаписать новый/ручной заголовок.

Во время основного первого ответа виден стандартный заголовок «Новая беседа».
После итогового ответа основной цикл освобождается сразу; заголовок обновляется
позже. Stop управляет основным циклом. При ошибке основной генерации используется
запасной заголовок. При новом сообщении во время запроса заголовка запасной
заголовок применяется сразу, новая основная генерация не ждёт его завершения.

На выбранной модели **google/gemma-4-e4b**, LM Studio `localhost:1234`, выполнены
три синтетических streaming-запроса с тем же системным промптом и без tools:

| Диалог | Время целого запроса | Результат |
| --- | ---: | --- |
| Большие файлы Downloads | 0.558 с | Найти большие файлы в Downloads |
| Расследование процесса на Mac | 0.356 с | Расследование подозрительных процессов Mac |
| Английские research notes | 8.392 с | Organizing research notes by project |

Среднее **3.102 с**, диапазон 0.356–8.392 с. Это три измерения, а не оценка
устойчивой производительности. LM Studio был временно недоступен во время
первых тестовых запусков и доступен при финальном измерении; Ollama недоступен.
В content «мусора» не было. В английском ответе присутствовал отдельный
`reasoning_content`, который существующий SSEParser не отображает. Встроенные
`<think>…</think>`, незакрытый think, markdown, кавычки, многострочность,
пустой ответ и лимит 60 символов проверены синтетическими тестами. Запасной
вариант нормализует пробелы и обрезает до 40 символов по границе слова с `…`;
единственное слово длиннее лимита обрезается по символам.

## 3. Системный промпт

Точка сборки: **SystemPromptBuilder**, `Core/WorkspaceSupport.swift`.
`ChatViewModel.persistPrompt` добавляет результат в начало requestMessages как
system message, без сохранения его в историю. Непустые инструкции добавляются
отдельным блоком `Инструкции проекта «<имя>»:\n<текст>` после base.
Пустые/пробельные инструкции не добавляются. Проверен фактический запрос
тестовому провайдеру.

Расхождение с описанием: на v0.4.1 обычный чат вообще не имел базового системного
промпта. Поэтому base по умолчанию пуст, и беседа без инструкций сохраняет
прежний состав запросов. Этот параметр — точка расширения для v0.5.
AgentLoop, SessionPermissions, ToolRiskEvaluator и движок разрешений не изменены.
Рабочая папка сохраняется после стандартизации/разрешения симлинков, но не влияет
на доступ инструментов. Проверки папки находятся в Security, а не в View.

## 4. Удаление во время генерации и интерфейс

ChatViewModel отдельно хранит ID генерируемой беседы, поэтому смена выбранной
беседы не меняет цель Stop. Подтверждённое удаление активной беседы сначала
вызывает существующий stopGeneration и откладывает удаление SwiftData-объектов
до выхода отменённого AgentLoop. Pending approvals отклоняются; запись
отменённого вызова остаётся в аудите. После удаления выбирается другая
неархивная беседа либо создаётся новый чат. При удалении проекта применяется
та же последовательность. Архивация активной беседы останавливает генерацию;
перенос и переименование её не останавливают.

Проверено автоматическими тестами: удаление во время стриминга, удаление проекта
во время pending approval, сохранность аудита и отсутствие сообщений удалённой
беседы. Это проверки модели, не ручное удаление живой беседы через UI.

В запущенной сборке через accessibility UI проверены секции Projects/Chats,
Show Archive, форма New Project, disabled Save при пустом имени, сообщение
ошибки при `/` и явный диалог подтверждения `/System`. Формы отменены без
создания тестовых проектов в пользовательском хранилище. Диалоги удаления
показывают предупреждение об остановке генерации; удаление проекта по умолчанию
переносит сессии в Chats. Новая беседа из toolbar наследует текущий проект;
из menu-bar popover создаётся обычный чат.

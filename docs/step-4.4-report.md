# Шаг 4.4 — Проектный периметр, инспектор, чип политики

Исходное состояние: `v0.4.3`, чистое рабочее дерево. План согласован сообщением
пользователя `ok`. Итоговая версия: `v0.4.4`. Реализован только шаг 4.4.

## 1. Контекст вызова и план реализации

Перед изменением движка добавлен `LegacyPolicyCharacterizationTests`: запись,
чтение, перемещение, разрешённая директория, выход через `..`, соседний путь с
похожим префиксом, allow/block и обход path-правил через `run_shell`.
Характеризационный тест прошёл на старом движке; исходный прогон после включения
нового файла в Xcode-проект: 179 тестов, 0 ошибок.

Существующие имена сохранены: `ToolRiskContext`, `SessionPermissions`,
`SecurityPolicyEngine`, `SessionRunner`, `AgentLoop`. Новый тип
`ToolInvocationContext` содержит обязательный UUID беседы, optional
`ProjectSecuritySnapshot` (UUID проекта, рабочая папка) и поколение памяти.
`AppState` не добавлялся.

Основные сигнатуры:

```swift
AgentLoop.streamResponse(
    to:using:invocationContext:onEvent:
)
// invocationContext: @MainActor @Sendable () -> ToolInvocationContext

SecurityPolicyEngine.init(rules:invocation:)
ToolRiskEvaluator.evaluate(_:arguments:context:invocation:)
Tool.execute(arguments:invocation:)
Tool.execute(arguments:invocation:policy:)
SessionPermissions.allows(conversationID:toolName:riskLevel:expectedEpoch:)
SessionPermissions.remember(conversationID:toolName:riskLevel:expectedEpoch:)
```

Раннер передаёт источник контекста своей конкретной беседы, а не выбранной в UI.
Перед каждым инструментом цикл на MainActor синхронно снимает проект и поколение
памяти, затем передаёт неизменяемый контекст в оценку, политику и исполнение.
Политика хранит этот контекст, включая проверки потомков в `list_dir` и
`search_files`. Ожидающее подтверждение сохраняет исходную политику и контекст.
Смена папки влияет на следующий вызов.

Поколение предотвращает две гонки: одобрение старого запроса не восстанавливает
очищенную память; старый снимок не использует разрешения, выданные после смены
папки. Это работает и при смене папки до создания карточки подтверждения.

В production нет контекст-свободного `execute` или входа в агентный цикл.
Отдельная отрицательная проверка `swiftc -typecheck` получила четыре ошибки
`missing argument` для исполнения, оценки риска, создания политики и входа в
цикл без контекста. Контекст-свободные адаптеры старых тестов существуют только в
тестовом таргете, с фиксированным UUID фикстуры. Они не входят в приложение или
реестр инструментов.

Проектные allow-паттерны используют существующую канонизацию и glob-семантику
политики. Block приоритетнее allow. Для проектной записи/перемещения проверяются
исходная и подготовленная формы путей, риск не снижается. Чтение остаётся safe
вне разрешённой зоны. Процессов для чтения Git-метаданных приложение не запускает.

## 2. Хранилище и встроенная защита

Фактическое существующее хранилище:

- `/Users/apetrenko/Library/Application Support/default.store`;
- соседние `default.store-wal` и `default.store-shm`.

Расположение не менялось. На старте `ApplicationProtection` получает URL из
конфигурации созданного контейнера, bundle ID — из `Bundle.main`. Для текущей
сборки ID: `local.maclm-agent`. Четыре обязательных глобальных block-правила:

1. `<фактический URL хранилища>*` — база и её служебные файлы;
2. `~/Library/Application Support/<bundle id>/**` — каталог данных приложения;
3. `~/Library/Preferences/<bundle id>.plist` — настройки;
4. `~/Library/LaunchAgents/**` — агенты запуска пользователя.

Они имеют `isBuiltIn = true`, `isMandatory = true`, всегда включены. Сидер
проверяет каждое правило и повторно проверяет результат сохранения. Ошибка
контейнера/защиты показывает критический диалог и завершает запуск, без
продолжения с отсутствующей защитой.

API редактора возвращает ошибку при изменении, отключении или удалении
обязательного правила. В UI соответствующие действия недоступны; отображается
замок. Сброс прежних 16 встроенных правил сохраняет обязательные правила.
Прежние встроенные правила остаются отключаемыми, как до шага 4.4.

`run_shell` по-прежнему dangerous, не соблюдает эти правила и может читать или
изменять перечисленные данные после подтверждения команды. Команды не
разбираются. Ограничение явно показано в инспекторе и поповере чипа.

## 3. Совместимость и тесты

Характеризационный тест и все прежние тесты проходят с явно заданным контекстом
беседы без проекта. Проект без папки использует глобальные правила и
`allowed_dirs`. Единственное намеренное расширение глобальной защиты — четыре
новых обязательных block-правила.

Новые проверки покрывают:

- проектную папку, `..`, симлинк наружу, похожий префикс;
- отключение глобальных allow/`allowed_dirs` внутри проектного периметра;
- глобальный block и allow только своего проекта;
- два независимых параллельных цикла с разными проектами;
- снимок ожидающего запроса и новую папку для следующего вызова;
- смену папки между снятием снимка и вычислением риска;
- изоляцию памяти бесед, запрет памяти dangerous, очистку при смене папки,
  переносе и удалении, защиту от устаревшего поколения;
- четыре защитных правила, запрет изменения через API и исключение `run_shell`;
- Git branch, detached HEAD, отсутствие `.git`, worktree с `.git`-файлом;
- скрытые файлы и ограничение страницы дерева 500 элементами;
- полноту ru/en каталога и миграцию отдельной копии реального хранилища.

Форка бесед в текущем приложении нет: он относится к шагу 4.5. Новая беседа
получает новый UUID и пустую память.

Финальный полный прогон выполнялся из независимой копии исходников в `/tmp`:
190 тестов, 0 ошибок, 1 пропуск. Пропущен старый
`SessionLoadTests.testMigrationOnLocalRealV042Snapshot`: его локальная фикстура
`build/step43-validation/before.store` не входит в независимую копию. Новый тест
миграции реального v0.4.3-хранилища выполнен, не пропущен.

Debug собирается в рамках `make test`; отдельный `make build
CONFIGURATION=Release` также проходит. Release запущен с хранилищем в памяти
через существующий механизм тестового запуска.

`git diff --check` проходит. Полный SwiftLint остаётся красным: 42 замечания
против 43 на `v0.4.3`; сравнением файла/правила подтверждено отсутствие новых
замечаний. Исправление накопленного lint-долга не входит в этот шаг.

## 4. Миграция и изоляция проверки

В SwiftData добавлены только `SecurityRule.project: Project?` (nil по умолчанию)
и `SecurityRule.isMandatory: Bool = false`. Существующие поля не удалены и не
переименованы. Миграция автоматическая, без переноса базы.

До миграции отдельно скопированы реальный `default.store`, WAL и SHM. Тест
создаёт ещё одну временную копию этой фикстуры и открывает только её. Исходные
количества получены чтением SQLite-копии и сравнены после миграции:

| Сущность | До / после |
|---|---:|
| Conversation | 9 / 9 |
| Project | 0 / 0 |
| Message | 58 / 58 |
| ToolCall | 20 / 20 |
| ClipboardAction | 6 / 6 |
| SecurityRule до сидирования | 16 / 16 |
| AuditEntry | 0 / 0 |

У старых правил `project == nil`, `isMandatory == false`. Сидирование добавляет
четыре обязательных правила; повторное сидирование не создаёт дублей.
Повторное открытие мигрированной копии успешно.

У боевых store/WAL/SHM после проверок SHA-256 и `mtime_ns` совпадают с исходными.
Тестовый host и проверка запуска используют хранилище в памяти.

## 5. Инспектор и чип

Без проекта: «Без проекта», выбор проекта для переноса, отсутствие дерева
рабочей папки, глобальные правила, разрешения и последние 20 записей своей
беседы. Для проекта без папки: имя проекта, «Рабочая папка не задана», изменение
папки через существующий валидатор, глобальная политика; ветки и дерева нет.

Для проекта с папкой: имя/путь, Finder, изменение папки, branch или короткий
hash detached; ленивый `OutlineGroup`, скрытые файлы исключены, максимум 500
записей на уровень и «Ещё N». Двойной клик открывает Quick Look, контекстное меню
— Finder. Каталоги читаются вне MainActor; это UI-действие без записи в аудит.

Безопасность и поповер чипа используют общий `SessionPolicyView`: зона,
количество действующих path block-правил, разрешения этой беседы, отзыв, сброс,
постоянная оговорка о чтении и `run_shell`. Чип показывает проектную/глобальную
политику и ненулевое количество разрешений. Под композером — проект и Git-ветка;
счётчик контекста не реализован. Инспектор сохраняет состояние открытия.
Журнал открывается с фильтром UUID беседы и позволяет снять фильтр.

Интерактивная проверка ограничена: Debug-приложение запущено с базой в памяти,
через Accessibility прочитано главное окно с новым чипом и кнопкой инспектора.
При попытке открыть инспектор канал Computer Use завершился ошибкой
`Sky Computer Use native pipe closed before response`, в том числе после сброса
сессии инструмента. Полный ручной проход инспектора/Finder/Quick Look не
подтверждён; сборка, запуск и перечисленные автоматические проверки подтверждены.

Коммит: `feat(security): project perimeter, per-conversation session memory and inspector`.
Тег: `v0.4.4`. Публикация в remote не выполнялась.

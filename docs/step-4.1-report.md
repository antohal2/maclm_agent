# Шаг 4.1 — Настройки, локализация, провайдеры

Дата: 2026-10-05. Исходная версия: `v0.4.0`. Результат: `v0.4.1`.

## 1. Исследование API

### LM Studio 0.4.25+1 — проверено на живом сервере

Версия взята из `CFBundleShortVersionString` установленного `/Applications/LM Studio.app`.
В начале проверки порт 1234 не отвечал; позднее сервер стал доступен.
Сохранены полные ответы GET `/api/v1/models`, `/api/v0/models`, `/v1/models`
в `maclm-agentTests/Fixtures/*live-0.4.25.json`. Они не содержат переписки,
содержимого файлов, путей пользователя или секретов.

| Endpoint | Идентификатор / тип | Загрузка | Контекст | Tools |
|---|---|---|---|---|
| `/api/v1/models` | `models[].key`, `type`: `llm` / `embedding` | `loaded_instances` | `max_context_length`; отдельно `loaded_instances[].config.context_length` | `capabilities.trained_for_tool_use` |
| `/api/v0/models` | `data[].id`, `type`: `llm` / `vlm` / `embeddings` | `state`: `loaded` / `not-loaded` | `max_context_length` | в снятом ответе нет; `nil` |
| `/v1/models` | `data[].id` | не используется для вывода о загрузке | нет | нет |

Реальный пример v1 для `google/gemma-4-e4b`: `type: "llm"`, непустой
`loaded_instances`, `max_context_length: 131072`,
`loaded_instances[0].config.context_length: 131072`,
`capabilities.trained_for_tool_use: true`.
Для `text-embedding-nomic-embed-text-v1.5`: `type: "embedding"`,
`loaded_instances: []`, `max_context_length: 2048`, `capabilities` отсутствует;
`supportsTools` остаётся `nil`.

Сервер вернул повторные `key` для некоторых моделей. Discovery убирает
дубликаты по id, предпочитая запись с загруженной моделью.
`vlm` в v0 относится к чат-моделям.

Discovery сначала проверяет существующий `/v1/models`, затем дополняет результат
из native v1, при недоступности — v0. При отсутствии native API остаются id
и эвристический фильтр. Неизвестные значения не заменяются выдуманными данными.

`ModelInfo.contextLength` в этом шаге означает **максимум модели**, а не текущий
размер контекста загруженного экземпляра. Для 4.7 нужно отдельно учитывать
конфигурацию выбранного instance и поля usage. `trained_for_tool_use` означает
заявленную провайдером обученность для tools; это не проверка корректности
вызовов. AgentLoop и передача инструментов не изменены.

Документация: [native v1](https://lmstudio.ai/docs/developer/rest/list),
[v0](https://lmstudio.ai/docs/developer/rest/endpoints).

### Ollama — не проверено на живом сервере

`localhost:11434` не отвечает, `/api/version` недоступен. Приложение Ollama
в `/Applications` и CLI в PATH не найдены; установленная версия не установлена.
Фикстуры `ollama-*-synthetic.json` синтетические по официальной документации.
Название файлов и комментарий в тестах явно отмечают это.

| Endpoint | Использование |
|---|---|
| GET `/api/tags` | `models[].name` с fallback на `model` → id |
| POST `/api/show`, тело `{ "model": id }` | `capabilities`: `completion` → chat, `embedding` → embedding; `tools` → supportsTools; `model_info[general.architecture + ".context_length"]` → максимум контекста |
| GET `/api/ps` | членство модели в `models` → isLoaded; отсутствие ответа → `nil` |

Отсутствие `capabilities` не означает `false`: поля остаются `nil`.
При наличии массива capabilities отсутствие `tools` означает `false`.
`/api/ps` может отдавать `context_length` активной модели — это отдельный вход
для 4.7, не подмена максимума модели.

Источники: [show](https://docs.ollama.com/api-reference/show-model-details),
[ps](https://docs.ollama.com/api/ps),
[API schema](https://github.com/ollama/ollama/blob/main/docs/openapi.yaml).

Запросы выполняются асинхронно с таймаутом 1.5 секунды на запрос; эндпоинты
обнаруживаются параллельно. Дополнительные запросы идут только к тому же
провайдеру. Redirect на иной origin отклоняется. Не добавлены зависимости,
облачные обращения, запросы загрузки моделей или изменение AgentLoop.

## 2. Настройки и перенос разделов

Пять вкладок, в порядке: Основные / Модели / Безопасность / Буфер обмена /
Внешний вид. Каждая использует `Form(.grouped)`; окно 900 × 680 pt,
контент сверху и прокручивается.

- Основные: язык, прежний глобальный хоткей панели.
- Модели: прежняя вкладка провайдера; LM Studio и Ollama показываются всегда,
  отдельные секции для сохранённых пользовательских адресов, немедленный выбор
  модели, раскрывающаяся секция добавления адреса. Поле ручного id и «Применить»
  убраны из UI. Чип композера открывает Settings → Модели.
- Безопасность: существующий редактор правил, allowed_dirs, срок хранения,
  очистка и открытие журнала, текущие запомненные разрешения. Изменена только
  локализация текста UI; логика разрешений и хранения не менялась.
- Буфер обмена: прежний редактор, авто-вставка, Accessibility и хоткей пикера.
- Внешний вид: прежняя тема.

Реальные имена: `AppSettings`, `ProviderCoordinator`, `ProviderSelectionStore`,
`DetectedProvider`, `ChatStreamEvent`. `ModelInfo` добавлен; `AppState` не вводился.
`DetectedProvider.availableModels` теперь `[ModelInfo]`; протокол LLMProvider
и streamChat остаются прежними. Настройка модели остаётся глобальной.

## 3. Локализация и граница протокола

`Localizable.xcstrings` содержит ru/en для всех записей, включая вычисляемые
подписи, AppKit-диалоги, ошибки редактора, хоткеев и Clipboard Actions,
подтверждения, журнал, пустые состояния и accessibility/help.
Статические String-подписи используют `String(localized:)`; SwiftUI
интерполяции используют String Catalog. Компиляторская выгрузка stringsdata
сверена с каталогом: отсутствующих ключей нет.

Выбор сохраняет `interface.language` и `AppleLanguages` в UserDefaults
приложения. «Системный» удаляет собственный AppleLanguages; системный список
языков macOS не меняется. Собственный ключ отличает выбор от глобально
унаследованного AppleLanguages. Эффективный язык меняется после перезапуска.

Без перевода остаются намеренно:

- имена инструментов, model id, URL, пути, SF Symbols, технические значения
  `safe/caution/dangerous`, `allow/block`, `tools`, `LAN`;
- системный промпт, описания и схемы инструментов, шаблоны Clipboard Actions,
  результаты инструментов, `Cancelled by user`, содержимое аудита;
- сообщения модели, пользовательские названия и описания, сохранённые данные,
  внешние диагностические тексты сервера/ОС.

Встроенные названия действий и причины риска переводятся **при отображении**
через InterfaceLocalization; сохранённые значения и снимки для протокола не
переписываются. Отображение стандартного заголовка беседы также не меняет данные.
Тексты новых уведомлений, проектов, питомца и контекстного счётчика не вводились.

## 4. Миграция и безопасность адресов

Старые ключи `llm.selectedProvider`, `llm.baseURL`, `llm.selectedModel` остаются
единственным хранилищем активного выбора. Сохранённый адрес добавляется к списку
пользовательских секций при чтении. Дополнительные адреса хранятся в
`llm.endpoints` как Codable JSON. Добавление адреса не заменяет активную модель;
выбор происходит в списке обнаруженных моделей.

Сохранённый не-loopback адрес не требует повторного подтверждения; недоступность
сервера не стирает выбор. LAN показывается соответствующей меткой, внешний
адрес — красным предупреждением. Новые адреса проверяются чистым классификатором
по строке, без DNS. LAN и внешние адреса не сохраняются без подтверждения.
Userinfo в новых URL отклоняется. Loopback включает весь 127/8 и IPv6 ::1;
LAN — RFC1918, link-local, IPv6 ULA и *.local.

Из выбора и автоматического разрешения исключены embedding-модели; при неизвестном
kind применяется case-insensitive `embed`. Явный kind chat имеет приоритет над
эвристикой. Дополнительная проверка перед созданием провайдера не позволяет
использовать ранее сохранённую embedding-модель для чата. Включение «Показать
скрытые модели» показывает серые неактивные строки.

SwiftData-модели и схема не изменены. Обычный запуск открыл существующее хранилище:
в сайдбаре доступны прежние беседы и сохранённые сообщения/tool calls.

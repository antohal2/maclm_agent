# Шаг 4.7 — модель сессии и контекст

Дата: 2026-10-06 (Asia/Novosibirsk). Исходный тег: v0.4.6. Выходной тег: v0.4.7.

## 1. Провайдеры, лимит и usage

- Идентификатор провайдера — существующий ключ секции DetectedProvider.id:
  тип + "|" + нормализованный URL. ProviderEndpoint.id повторяет этот ключ.
  В llm.endpoints сохраняется пара provider/baseURL, отдельного UUID нет.
- Conversation.modelID/providerID: nil наследует глобальный выбор; явный выбор
  сохраняется независимо от настройки по умолчанию. Форк наследует оба поля.
  AutoTitleService получает тот же экземпляр провайдера, что использовал раннер.
- LM Studio **0.4.25+1**, установленная версия проверена по Info.plist.
  Живой /api/v1/models сохранён в lmstudio-models-live.json. Загруженная
  google/gemma-4-e4b: loaded_instances[0].config.context_length = **131072**;
  max_context_length = 131072. Остальные чат-модели в ответе не загружены;
  их максимум 262144 не используется как лимит.
- При нескольких loaded_instances берётся первый экземпляр ответа.
- Живой SSE /v1/chat/completions с stream_options.include_usage=true:
  prompt_tokens=21, completion_tokens=2, total_tokens=23; usage пришёл в
  отдельном чанке с choices=[]. Фикстура lmstudio-usage-live.sse сохранена.
  Запрос выполнен к уже загруженной Gemma; загрузка/выгрузка и num_ctx не менялись.
- Ollama недоступен на localhost:11434: **не проверено на живом сервере**.
  Синтетические фикстуры явно помечены и основаны на
  [chat](https://docs.ollama.com/api/chat) и [ps](https://docs.ollama.com/api/ps).
  Usage разбирается из prompt_eval_count/eval_count финального объекта;
  лимит — context_length совпадающей модели из /api/ps.
- Нет loadedContextLength → редактируемый llm.defaultContextLimit, исходно 8192,
  «≈» и пояснение неизвестного фактического лимита. Максимум модели — в help
  счётчика, никогда не его знаменатель.
- Usage сохраняется как сумма последнего запроса; перед каждым запросом,
  включая промежуточный в AgentLoop, старое значение сбрасывается.
  Нет usage → «—». Автозаголовок счётчик беседы не перезаписывает.
- Метаданные обновляются при выборе беседы, открытии меню и завершении прогона,
  в том числе отменённого. Использован прежний ProviderDiscovery с таймаутом
  каждого metadata-запроса 1,5 секунды и параллельным обнаружением эндпоинтов.
  Отдельный callback сохраняет существующий обработчик уведомлений.

## 2. Tool calling при заполнении контекста

Измеренный порог деградации **не установлен**: живой smoke-запрос занимал только
23 / 131072 токена (~0,018%) и не проверял длинную цепочку tool calling.
70% и 90% — пороги отображения UI, а не экспериментально доказанные границы
надёжности модели. Наблюдения на длинных цепочках остаются открытым исследованием;
выводы о поведении Qwen/Gemma при 70–90% не делались.

Явный supportsTools=false фиксируется при старте прогона и отключает передачу
и исполнение инструментов. Неизвестная поддержка (nil) сохраняет прежний набор.
Проверки политики, подтверждений и аудита не изменены.

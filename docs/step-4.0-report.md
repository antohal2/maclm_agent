# Шаг 4.0 — каркас главного окна

## Изменения

NavigationSplitView и сцена Window сохранены. List получил явный стиль sidebar;
пользовательского фона и дублирующего переключателя сайдбара в исходном коде
не было. Сохранена одна кнопка новой беседы в системном toolbar сайдбара.
Лента и композер центрированы и ограничены 760 pt с учётом внешних отступов.
SwiftData-модели и схема не менялись. Следующие шаги Workspace не реализованы.

1. Правая кнопка server.rack открывала ProviderSettingsView в popover.
   Удалена из MainWindowView; тот же работающий раздел настроек открывается
   из чипа модели в ComposerView. Полный id доступен через help.
2. Stop отменяет generationTask. Завершение итерации AsyncThrowingStream вызывает
   onTermination провайдера, который отменяет task получения HTTP-ответа.
   Отмена также передаётся инструменту; существующая реализация run_shell
   завершает группу процессов. Pending-карточки текущей генерации передаются
   существующему resolveConfirmation как rejected. ConfirmationCoordinator уже
   поддерживает отмену ожидания. Единственная правка AgentLoop —
   Task.checkCancellation сразу после waitForDecision: при гонке с Reject
   отмена не превращается в обычный отказ с дальнейшим запросом модели.
   Аудит выполняется существующим кодом: cancelled / Cancelled by user.
   Карточки без результата получают Cancelled by user и соответствующее tool-
   сообщение для целостного следующего запроса. Частичный текст сохраняется;
   пустое сообщение без toolCalls удаляется. Ошибки транспорта при отменённой
   задаче тоже обрабатываются как отмена, а не заменяют текст сообщением ошибки.
   Send доступен после завершения очистки задачи; параллельной генерации нет.
3. Popover NSStatusItem использует тот же ChatView и ChatViewModel, поэтому
   ComposerView, чип модели и Stop доступны и там. MenuBarExtra не добавлялся.
4. TextField(axis: .vertical), lineLimit(1...8), focusEffectDisabled и собственная
   рамка. onKeyPress(keys: [.return], phases: .down) обрабатывает Enter;
   Shift+Enter передаётся нативному редактору. Если firstResponder — NSTextView
   с hasMarkedText(), Enter передаётся редактору для завершения IME, без send.
   Пустой/пробельный ввод не отправляется. Содержимое, включая переносы и
   внешние пробелы, сохраняется без trimming. Интерактивный IME-тест не выполнен.
5. Проверки: xcodebuild test, macOS, 141 тест / 0 ошибок. Новые тесты проверяют
   сокращение id, правило отправки, сохранение переносов, Stop при стриминге,
   Stop при ожидании подтверждения с аудитом отмены и Stop при выполнении
   отдельного тестового инструмента. Инструмент не добавлен в production registry.
   Существующие тесты cancellation/timeout run_shell и миграции проходят.
   GUI: собранная Debug-версия запущена, существующее хранилище открылось,
   старые беседы и результаты инструментов видны; проверены широкое окно,
   светлая тема, выбор беседы, ввод текста, отключение Send на пустом поле,
   расположение чипа и отсутствие старой кнопки провайдера. Пробный ввод очищен.
   Узкое окно, тёмная тема, физические Enter/Shift+Enter и IME, Stop через
   реальные LM Studio/Ollama и в status-item popover вручную не проверены.
   Автоматизированная отправка клавиш через Computer Use не дала надёжного
   подтверждения Enter/Shift+Enter, поэтому она не считается успешным тестом.

Дополнительные зависимости, обращения к новым сетевым сервисам и изменения
SessionPermissions / ToolRiskEvaluator / policy engine отсутствуют.
Названия типов соответствуют существующему коду, переименований нет.

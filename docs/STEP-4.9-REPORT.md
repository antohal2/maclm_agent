# Шаг 4.9 — пузырь питомца, Quick Chat, подтверждения caution

Дата проверки: 6 октября 2026, Asia/Novosibirsk. Исходное состояние: `v0.4.8.1`. Результат: `v0.4.9`.

1. **Фокус и активация.** `PetBubblePanel` — borderless nonactivating-панель, никогда не main. `canBecomeKey` разрешён только при явном входе в `PetQuickField`; поле не принимает автоматический initial responder. После успешной отправки снимается first responder, панель убирается и возвращается без активации; при закрытии остаётся скрытой. Заблокированный Enter сохраняет текст и фокус. Нативные тесты dispatch проверяют вход, Enter, Esc и неизменность PID активного приложения. Глобального монитора клавиатуры нет. Для VoiceOver поле предоставляет действие активации; полноценный проход VoiceOver остаётся ручной проверкой.

2. **Аудит и хранилище.** Источник записан суффиксом `[approvalSource: pet]` или `[approvalSource: feed]` в существующий `resultSummary`. Запись идёт существующим audit sink, включая отклонение и отмену. JSONL сохраняет суффикс; экспорт проверен тестом. Этот вариант сохраняет текущую SwiftData-схему: поля и migration plan не менялись, новая миграция и её проверка на копии хранилища не требуются. Боевой store в тестах не открывался.

3. **Граница подтверждения.** `Security/PetApprovalPolicy.swift` содержит чистую политику: pet approve разрешён только для эффективного caution и выключенной приватности. `SessionRunner.resolveApproval` проверяет UUID текущего `pendingApproval`, принадлежность беседе/сообщению и pending-статус, затем политику по риску из `ConfirmationRequest`, а не из UI. Приватность читается через замыкание общих настроек; отказ логируется и не меняет pending-вызов. Reject допустим независимо от риска/источника. Источник pet принудительно отключает rememberForSession. В `AgentLoop.resolveConfirmation` дополнительно проверяются существование запроса и caution для pet; классификация, исполнение и реестр не изменены. Тесты реального раннера проверяют dangerous, скрытый caution, старый UUID A при ожидании B, отсутствие памяти и совместимость источника feed по умолчанию.

4. **Имена и интеграция.** Использованы существующие `ApplicationRuntime`, `ChatViewModel`, `SessionRunnerRegistry`, `SceneActions`. В ленте остаётся `ChatViewModel.resolveConfirmation(toolCallID:decision:rememberForSession:)`, в раннере — `resolveApproval(id:decision:rememberForSession:source:)`; переименований нет. Имя выполняемого инструмента уже доступно в `SessionStatus.toolRunning`. Добавлен read-only `pendingApproval`. Общий перехват `/pet` — `ChatViewModel.handlePetCommand`, обе точки отправки используют его и `SessionRunner.send`. Новая беседа создаётся без проекта. Удаление выбранной цели принудительно включает новый Quick Chat, даже если главное окно автоматически выбрало другую беседу. Несколько persistence-помощников раннера вынесены в отдельный extension для соблюдения лимита длины файла SwiftLint.

5. **CPU и ресурсы.** Обычная ad-hoc Release-сборка с включённым Hardened Runtime показала в Activity Monitor 0,4–0,6% CPU при закрытом пузыре. В отдельном оптимизированном Release XCTest-замере одного видимого питомца: закрытый пузырь **0,97%**, открытый пустой пузырь **1,66%**, окна измерения по 12 секунд. В тестовом хосте отключён coverage, другие панели питомца временно скрыты без записи настроек. Только для загрузки XCTest использованы ENABLE_TESTABILITY=YES и ENABLE_HARDENED_RUNTIME=NO; финальная обычная сборка снова с Hardened Runtime, подпись проверена codesign. Прямой UI-инструмент не смог подключиться к новой сборке (Sky native pipe closed); поэтому открытый пузырь измерен нативным тестом, а не отдельным наблюдением Activity Monitor. Пузырь не создаёт таймеров, содержимое и мониторы мыши удаляются при закрытии; одноразовый Observation callback после закрытия не возобновляет подписку.

6. **Мониторы и fullscreen.** Геометрия ограничена visibleFrame экрана панели питомца, выбирает сторону с местом и проверена для отрицательных координат, краёв и NaN. Пузырь следует за перемещением/изменением размера питомца и пересчитывается при изменении экранов. Обе панели используют canJoinAllSpaces/fullScreenAuxiliary. Физическое переключение нескольких мониторов и fullscreen другого приложения в этой сессии не проверено; это остаётся ручным smoke test.

7. **Ручной проход.** Проверить caution approve/reject при закрытом главном окне; dangerous и скрытый caution — только «Открыть в чате»; приватность заголовков, инструментов и accessibility labels; переход по строке и сброс непрочитанного результата; Quick Chat в последнюю/новую беседу, удалённую цель и занятый раннер; `/pet` без сообщений; возврат фокуса предыдущему приложению после Enter, Esc и клика снаружи; выключение питомца; уведомление подтверждения при включённом подавлении завершения; VoiceOver, Reduce Motion, второй монитор и fullscreen.

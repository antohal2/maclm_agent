# Step 5.1 — catalog, suggest_skill, session attach

Дата: 2026-10-21. Исходный код: `v0.5.0.1` (`e8401c9`). Версия результата: `v0.5.1`.
SPEC, раздел 15 (Rev 5), прочитан до реализации; конфликтов с заданием не обнаружено.

## Реализация

- `SkillCatalogBuilder`: только enabled, максимум 20 записей, имя до 64 символов,
  общий бюджет min(5% окна, 2000 токенов), неизвестное окно 8192, оценка ceil(UTF-8/3).
  Сортировка предусматривает pinned, затем lastUsedAt, затем имя; проектные закрепления
  пока пусты. Каталог и Settings используют существующий `catalogDescription` с «…».
  Описания кодируются JSON-строками, чтобы переносы не создавали поддельные записи.
- `SessionSkills`: до трёх подключений, суммарно до 25% контекста, включая обёртки.
  Превышение бюджета отклоняется с уведомлением; инструкции не обрезаются.
  `SkillStore.verifiedAttachment` делает один проход папки существующим сканером:
  SKILL.md читается один раз через SkillFileIO, текст и хэш получаются из этих байтов.
  Несовпадение проходит через существующий переход доверия и аудит hashMismatch.
- В SwiftData добавлены optional `Conversation.attachedSkillsData`,
  `Conversation.declinedSkillsData`, `SkillRecord.lastUsedAt`.
  Подключение хранит id, hash и source, без текста. После перезапуска текст
  перечитывается и проверяется; выключенные, изменённые и повторно подтверждённые
  с другим хэшем навыки отключаются с уведомлением и аудитом. Открытие сессии
  и начало генерации также обновляют проверку доступности.
- Системный промпт пересобирается перед каждым запросом модели: инструкции проекта,
  каталог, подключённые инструкции в точной обёртке SPEC. Все варианты `</skill`
  нейтрализуются без учёта регистра. После клика Attach следующий запрос уже
  содержит инструкции, результат инструмента содержит только статус.
  Между запросами обновляются метаданные из общего SkillStore без чтения файлов.
- `suggest_skill` зарегистрирован как safe и проходит существующий путь оценки
  риска, политики и аудита. Отдельная карточка содержит имя, описание, причину,
  источник, размер, оценку токенов с обёрткой, короткий хэш и две кнопки.
  Ожидание устанавливает needsApproval; одновременно допускается одно предложение.
  Отказ запоминается для этой сессии, включая её восстановление. Подтверждение
  из пузыря питомца запрещено: доступно только «Открыть в чате».
- Добавлены popup по `@` и кнопка `@ Навыки`, фильтр включённых навыков, подключение
  по выбору пользователя с теми же проверками, чипы с отключением и раздел инспектора.
  Settings объясняет передачу текста после подключения и отмечает записи, не вошедшие
  в каталог для модели выбранной сессии.
- Аудит: skill.proposed, skill.attached, skill.declined, skill.detached, с source,
  hash и conversationID; причины отключения user / relaunchMismatch / disabled.
  Формат JSONL не изменён. Новые UI-строки имеют ru/en переводы.
- Используется единственный SkillStore из ApplicationRuntime. Новых зависимостей,
  сетевых обращений или путей чтения файлов навыков не добавлено. Политика,
  уровни риска, память caution и встроенная блокировка данных приложения сохранены.

## Ручная проверка

Ручной проход интерфейса и проверка с реальной LLM не выполнялись. Работа цепочки
проверена автоматическим провайдером; визуальное качество popup и карточки остаётся
проверить в запущенном приложении.

1. Поместить валидный навык в папку приложения, открыть Settings → Skills,
   пересканировать и включить. Проверить описание, «…», новый поясняющий текст
   и отметку исключения из каталога при превышении бюджета.
2. Выбрать локальную модель с поддержкой native function calling. Запросить:
   RU: «Предложи включённый навык, который поможет с этой задачей: …».
   EN: “Suggest an enabled skill that helps with this task: …”.
3. Проверить карточку, состояние ожидания и отсутствие «запомнить».
   В пузыре питомца должна быть только кнопка «Открыть в чате».
4. Нажать «Подключить»: проверить чип, раздел инспектора и продолжение ответа.
   Отключить навык чипом и через инспектор; проверить журнал.
5. Ввести `@` или нажать `@ Навыки`, выбрать включённый навык. Проверить,
   что он подключился без второй карточки, а введённый @-запрос удалён из поля.
6. Нажать «Не сейчас», попросить тот же навык повторно: новой карточки быть не должно.
   Отменить генерацию при ожидающем предложении и проверить отсутствие зависания.
7. Подключить три навыка, попробовать четвёртый и слишком большой навык:
   проверить понятный отказ и сохранность существующих подключений.
8. Перезапустить приложение с неизменённым навыком. Затем повторить с изменением,
   выключением и reconfirm с новым хэшем: старое подключение должно удалиться
   с уведомлением и skill.detached, новый текст не должен подключаться автоматически.
9. С враждебным навыком попросить dangerous-действие: должна остаться обычная
   карточка риска. Проверить русскую и английскую локализацию новых элементов.

# Шаг 3.5 — Укрепление run_shell

Предыдущее состояние: v0.3.5. Результат: v0.3.6.

## 1. Запуск и завершение группы

Foundation Process заменён только внутри RunShellTool на posix_spawn(`/bin/zsh`, `-c`, точная команда). POSIX_SPAWN_SETPGROUP и pgroup=0 создают группу с PGID=PID основного процесса. Собственные pipe подключаются file actions к stdout/stderr; stdin и окружение наследуются, cwd не задаётся. POSIX_SPAWN_CLOEXEC_DEFAULT закрывает посторонние дескрипторы приложения; стандартные сигналы и маска явно сбрасываются. Это устраняет также обнаруженную тестом утечку чужого pipe при конкурентном запуске процессов.

Таймаут или отмена → SIGTERM всей группе через killpg → до 2 секунд с чтением вывода и проверкой завершения → SIGKILL, если группа ещё существует. После нормального завершения zsh оставшаяся группа очищается в том же порядке. Фоновая работа в группе не сохраняется.

Чтение обоих каналов — O_NONBLOCK, обход каждые 10 мс; на канал максимум 16 чтений по 16 КиБ за обход, чтобы непрерывный вывод не задерживал проверку таймаута. После очистки группы — максимум 2 секунды на EOF/основной процесс; затем дескрипторы закрываются и накопленные данные возвращаются. Общий предел после таймаута: около timeoutSeconds + 2 с + 2 с и небольшой overhead. Полный объём вывода по памяти, как и раньше, не ограничен.

POSIX-поллинг выполняется на DispatchQueue, через throwing continuation, вне кооперативного исполнителя Swift. Отмена передаётся потоко-безопасным флагом; очистка сама не отменяется, затем выбрасывается CancellationError. AgentLoop, ToolRiskEvaluator и SessionPermissions не менялись.

## 2. Автоматическая проверка

Полный make test: 136 тестов, 0 failures, около 10.7 секунд. Лог: /tmp/maclm-shell-verified-tests.log.

Новые ShellProcessTests запускают реальные процессы с UUID-маркером argv и проверяют отсутствие маркера через ps; defer обеспечивает аварийную очистку:

- таймаут команды с sleep-потомком: возврат менее 6 с, timedOut=true, вывод before-timeout сохранён, потомок отсутствует;
- отмена после наблюдаемого старта потомка, который игнорирует TERM: SIGKILL работает, CancellationError возвращается менее 5 с, потомков нет (около 2.3 с);
- команда с `&`: exitCode=0 и timedOut=false сохранены, фоновый процесс остановлен, lifecycleNote отражён в результате и AuditSanitizer.summary;
- escaped-потомок через системный Perl/setsid с handshake: основной процесс завершается, pipe остаётся открытым, вызов возвращается менее 5 с с накопленным выводом и пометкой усечения; тест демонстрирует ограничение группы, самостоятельно убивает escaped-процесс и проверяет отсутствие остатка;
- описание содержит запрет файловых операций, причину и имена шести файловых инструментов.

Существующие тесты проверяют stdout/stderr, нормальный и ненулевой exitCode, таймаут как failure, отмену как cancelled, подтверждения, risk invariants и неприменимость path-политик к shell. Старый временной предел теста таймаута увеличен с 3 до 6 с под явные новые сроки очистки. Новых зависимостей и тестовых инструментов в registry нет. Xcode project дополнен только регистрацией файла тестов.

Финальный make build: BUILD SUCCEEDED, лог /tmp/maclm-shell-final-build.log. После тестов процессов с UUID-маркерами не обнаружено.

SwiftLint для RunShellTool и ShellProcessTests: 0 нарушений. У AuditEntry ранее существовало замечание opening_brace в многострочном if; оно не исправлялось в этом шаге. git diff --check прошёл. Xcode test host запускает собранное приложение; ручной UI/LLM-прогон не проводился.

## 3. Неохваченные ограничения и расхождения с запросом

- setsid/setpgid/демонизация позволяют покинуть группу; killpg такие процессы не завершает. Это прокомментировано в коде и SPEC; escaped pipe не может удерживать сам вызов бесконечно. Тест сам очищает процесс вне группы.
- Uninterruptible sleep не гарантирует немедленного действия SIGKILL. Вызов прекращает ожидание, поздний waitpid вынесен на utility queue для последующего reap. Реальное kernel D-state вручную не создавалось.
- Терминальная команда не может обещать остановку процесса, намеренно вышедшего из группы. Карточка сохраняет требуемую короткую фразу; точная граница описана в SPEC.
- Других production-запусков Process/posix_spawn в исходниках не найдено. Process в тестах используется для ps и не меняет поведение приложения.
- В текущем ChatViewModel нет метода Stop/cancel, в ChatView нет кнопки Stop. Есть generationTask, но UI-путь отмены ещё отсутствует. Он не добавлялся, поскольку это за пределами шага; отмена на уровне Tool/AgentLoop проверена тестами.
- Формат shell-команды, риск dangerous, отсутствие памяти/path enforcement, схема SwiftData, аргументы и dispatch/confirmation/audit flow не менялись. Из AuditEntry.swift изменён только AuditSanitizer.summary, чтобы перенести текст lifecycleNote в существующий resultSummary.

## 4. Формат результата и аудита

Прежние JSON-поля stdout, stderr, exitCode, timedOut сохраняются. При необходимости добавляется необязательный lifecycleNote — текстовая строка, без новых полей AuditEntry. Для обычной команды lifecycleNote отсутствует. Тот же текст добавляется в displayContent и в существующий resultSummary через AuditSanitizer.

Новые строки дословно:

```
Remaining background processes stopped.
Output truncated: a descendant kept an output pipe open.
```

Они означают соответственно «оставшиеся фоновые процессы остановлены» и «вывод усечён: потомок удерживал выходной pipe». Первая пометка применяется, когда после нормального завершения основного процесса остаётся группа. Вторая — когда до срока не получен EOF. Таймаут по-прежнему isError=true и outcome=failure; отмена выбрасывает CancellationError и outcome=cancelled. При отмене результат модели не возвращается, существующий AgentLoop записывает Cancelled by user; lifecycleNote в этот путь не передаётся, чтобы не менять запрещённую в шаге логику AgentLoop.

Описание для модели сохраняет исходное предложение и добавляет:

```
Do not read, write, move, delete files or browse directories with shell: it bypasses path access rules. Use read_file, write_file, move_file, delete_file, list_dir and search_files instead.
```

Это мягкая маршрутизация, без парсинга/запрета runtime и без изменения границы подтверждения. Комментарий рядом с description это фиксирует.

Новая строка карточки дословно:

```
По завершении команды все оставшиеся фоновые процессы останавливаются.
```

SPEC 5.2 и 6.6 обновлены; ROADMAP отмечает выполненные работы v0.3.6. В SPEC 9.1 не было отдельных будущих задач про cleanup/EOF/file-routing, поэтому этот раздел оставлен без изменений; direct, streaming UI, cwd, command и Terminal.app остаются v0.6.

## 5. Ручная проверка в приложении

1. Подтвердить run_shell с `sleep 300` и timeoutSeconds=1: возврат ограничен, timedOut=true, аудит failure.
2. Подтвердить команду с `&`, например `sleep 300 &`: возврат ограничен, потомка нет, пометка остановки видна в результате и журнале, exitCode исходной команды сохранён.
3. После появления кнопки Stop в предусмотренном будущем шаге: `sleep 300 & wait`, Stop после запуска, потомков нет, аудит cancelled. Сейчас этот UI-сценарий недоступен; эквивалентная Task cancellation выполнена автоматически.
4. Проверить карточку: полная команда и таймаут в прежнем порядке, новая строка о фоновых процессах, dangerous без запоминания.

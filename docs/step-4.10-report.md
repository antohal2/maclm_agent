# Шаг 4.10 — пользовательские питомцы, v0.4.10

## 1. Итог подфазы

Реализованы безопасный импорт папки, подтверждённая замена, список с миниатюрами,
мгновенный выбор, подтверждённое удаление, обновление и причины неисправности.
Пропавший или повреждённый активный питомец сбрасывается на встроенного при запуске
и перечитывании. Положение и масштаб сохраняются. Данные и выбор принадлежат
единому `ApplicationRuntime`; SwiftData, движок разрешений и пузырь не менялись.
Настройки тестового хоста изолированы отдельной suite, чтобы новый fallback
не менял реальные `UserDefaults` во время XCTest.

В v0.4.x также входят панель, анимация агрегированных состояний, drag/sleep,
reduce motion, `/pet`, меню и пузырь с сессиями, Quick Chat и подтверждениями
только `caution`. Следующая фаза — v0.5 Skills, её реализация не начиналась.

Отложено: встроенный арт `bronya` (пока Canvas-плейсхолдер), живые проверки
нескольких мониторов и fullscreen, DMG и публикация GitHub Release.
Скрипта `tools/assemble_pet.py` нет, новый скрипт не добавлялся.

## 2. Защита импорта

- `PetFileAccess` открывает папку и два фиксированных файла. Для файлов:
  `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`, `fstat`, только `S_IFREG`, лимит метаданных
  и ограниченное чтение из того же дескриптора. `O_NONBLOCK` предотвращает
  зависание при подмене на FIFO. После открытия смена имени не меняет читаемый файл.
- JSON ≤ 64 КиБ, PNG ≤ 8 МиБ. `PetLoader.load(manifestData:imageData:)` остаётся
  единым валидатором для встроенного, установленного и импортируемого арта.
  Размеры PNG проверяются до декодирования; максимум 16 777 216 пикселей.
- Идентификатор проверяется существующим контрактом `[a-z0-9-]{1,40}`.
  `bronya` зарезервирован; коллизии имён сравниваются без учёта регистра.
  Каталоги с нарушенным контрактом помечаются неисправными, их нельзя выбрать.
- Проверенные `Data` копируются без повторного чтения исходной папки.
  В `.import-<uuid>` записываются ровно два файла, выполняются `fsync` и повторная
  валидация с диска. Новая установка: `RENAME_EXCL`; замена: `RENAME_SWAP`.
  Отказ до атомарной установки оставляет старую папку нетронутой и удаляет staging.
  После успешного swap старый каталог удаляется из staging.
- Лимит 50 включает неисправные каталоги и ссылки. Замена не увеличивает число.
  Файлы и скрытые каталоги в список не попадают; ссылки показаны неисправными.
- Удаление рекурсивно привязано к дескрипторам папок через `openat`/`unlinkat`.
  Симлинки удаляются как ссылки; их цели не обходятся.
- Причины валидатора и категории файловых ошибок локализованы ru/en.
  Сырые ошибки, errno и технические сведения остаются в системном логе.
  Неотключаемое block-правило каталога данных остаётся действующим; есть отдельный тест Pets.

Атомарность относится к переключению каталогов при работающей файловой системе.
Отказ самой очистки (например, внешний процесс одновременно меняет права папки)
логируется; гарантия восстановления после аварии ОС или потери питания не добавлялась.

## 3. Граница данных и путей

`PetImport` хранит проверенный спрайт и закрытые для других файлов исходные байты.
UI передаёт выбранный `URL` в `PetStore.prepare`, а не строит пути назначения.
`PetManifest.validateIdentifier` проверяет `id` до операций с именами в `Pets`.
Открытый дескриптор корня является опорой для записи, rename и удаления;
файлы открываются с фиксированными именами и без следования симлинкам.
`NSOpenPanel` находится только в `PetSettingsView`. Ядро получает корень параметром.
Тесты используют временные каталоги и отдельные `UserDefaults` suites.

## 4. Имена и контракт

Источник истины — `ApplicationRuntime`, `PetController`, `PetLoader`, `AppSettings`;
`AppState` не вводился. Добавлены `PetStore`, `PetFileAccess`, `PetLibrary`,
`PetStorageError`, `PetImport` и `PetEntry`. Выбор: `AppSettings.petSelectedID`,
ключ `pet.selectedID` (существующего ключа выбора не было).

Сохранён id-контракт 4.8: `[a-z0-9-]{1,40}`, а не резервный вариант из задания
с подчёркиванием и длиной 32. Строки листа определяются `rows[].row`;
вопреки формулировке таблицы SPEC код не навязывает фиксированный порядок
всех восьми состояний. Высота — `(max row + 1) × 64`, не число записей × 64.
Контракт валидатора не расширялся, типы не переименовывались.

## 5. Проверки и CPU

`make lint`: SwiftFormat + strict SwiftLint, 0 нарушений.
Финальный `make test`: 279 тестов, 0 ошибок, 1 штатный пропуск, 48,58 секунды.
Проверялся каталог локализации на основе HEAD с добавлением только 20 новых строк;
посторонние изменения исходного каталога сохранены в рабочей копии и исключены из коммита.
Обычный `make build CONFIGURATION=Release` прошёл. `codesign --verify --deep --strict`
прошёл; flags `0x10002(adhoc,runtime)`. Приложение запущено, процесс PID 17407 жив.
Проверка окна/новой вкладки через UI automation не завершена: мост вернул
`Sky Computer Use native pipe closed before response`, повтор после reset дал ту же ошибку.
Это ограничение проверки UI, а не подтверждённый сбой приложения.

Измерение `PetResourceTests.testIdleCPUWithClosedAndOpenBubble`, Release `-O`,
видимый встроенный плейсхолдер ×2, 12 секунд на каждое состояние после прогрева:

| Версия | Пузырь закрыт | Пузырь открыт |
|---|---:|---:|
| v0.4.9 | 1,02% | 1,61% |
| v0.4.10 | 1,04% | 1,65% |

Activity Monitor: Release-процесс v0.4.10 PID 16928, 1,1% CPU, 26 idle wake-ups.
Разница +0,02 / +0,04 процентного пункта находится на уровне вариации короткого
замера; новые периодические задачи не добавлены. Это не статистическое доказательство
равенства, нагрузка большого пользовательского листа отдельно не измерялась.

Для загрузки XCTest в оптимизированный ad-hoc Release применялись только CLI overrides
`ENABLE_TESTABILITY=YES ENABLE_HARDENED_RUNTIME=NO` (иначе macOS отвергает тестовый dylib
с ошибкой разных Team IDs). Обычный Release отдельно собирается с исходным
`ENABLE_HARDENED_RUNTIME=YES`; настройки проекта не ослаблены.
Логи доступны в `/tmp/maclm-pet-{test,lint,409-release,410-release,prod-build}.log`.

## 6. Ручной checklist

1. «Добавить питомца…»: корректная папка, отображение имени/id/миниатюры и применение арта.
2. Симлинк на каждый обязательный файл: конкретный отказ, ничего не установлено.
3. Дополнительные файлы: импорт проходит, установлены только JSON и PNG.
4. `bronya` и `Bronya`: отказ; `..`, слеши и управляющие символы: отказ.
5. Повторный id: отмена сохраняет старого, подтверждение заменяет.
6. Удаление активного: встроенный выбран, положение и масштаб сохранены.
7. Ручная порча JSON/PNG в `Pets` + «Обновить список»: неисправный, причина, выбор недоступен.
8. Перезапуск с неисправным/удалённым активным: встроенный, сохранённый выбор сброшен.
9. Отдельно: несколько мониторов, fullscreen и длительный idle с собственным большим листом.

Файловые сценарии и fallback покрыты автоматическими тестами; полный ручной
прогон всех диалогов с записью в пользовательское хранилище не выполнялся.

## 7. Наблюдения для v0.5

Пузырь остаётся независимым от выбранного арта; его правила `caution`/`dangerous`
не меняются. Загрузка/выбор арта не создают таймеров и не меняют позицию панели.
Тест с открытым пузырём потребляет примерно на 0,6 п.п. CPU больше закрытого.
Удобство миниатюр, списка из 50 питомцев и диалогов замены требует пользовательской
оценки; не выдаём это за результаты UX-исследования. Источник approval в аудите
остаётся прежним; Skills не должны расширять права питомца.

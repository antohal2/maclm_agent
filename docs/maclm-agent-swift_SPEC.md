# maclm-agent — Техническая спецификация

**Revision 3** · macOS 15 Sequoia+ · Apple Silicon
**Изменения Rev 3:** переработан раздел 6 (модель безопасности: уровни риска, правила, аудит), добавлен раздел 9 (системная интеграция), обновлён раздел 10 под новый порядок фаз.

---

## 1. Обзор

`maclm-agent` — нативный AI-ассистент для macOS, работающий полностью офлайн через локально хостируемую LLM. Никаких облачных зависимостей, никакой телеметрии, никаких ключей от внешних сервисов.

**Стек:** Swift 6, SwiftUI, SwiftData
**Минимальная цель:** macOS 15 Sequoia, Apple Silicon
**Провайдеры LLM:** LM Studio, Ollama (в перспективе — MLX)
**Распространение:** прямое, ad-hoc подписанный DMG через GitHub Releases. Без App Store, без sandbox-энтайтлмента, без нотаризации (с возможностью перейти на неё позже).

### 1.1 Принципы

1. **Каждый этап = работающий продукт.** Ни один шаг не оставляет приложение в нерабочем состоянии.
2. **Локальность по умолчанию.** Любая сетевая активность — только к `localhost`.
3. **Человек в контуре.** Ни одно потенциально разрушительное действие не выполняется без явного подтверждения.
4. **Расширяемость через протоколы.** Провайдеры и инструменты добавляются без переписывания ядра.

## 2. Архитектура

```
App/            точка входа, WindowGroup + MenuBarExtra, общий AppState
Core/           агентный цикл, роутинг вызовов инструментов, состояние беседы
LLM/            протокол LLMProvider, реализации LMStudio / Ollama, стриминг
Tools/          протокол Tool, реестр, реализации инструментов
Security/       уровни риска, правила, движок разрешений, аудит
Persistence/    SwiftData-модели, контейнер, миграции
Clipboard/      модуль Clipboard Actions (см. раздел 8)
UI/             представления чата, настроек, пикера, редакторов
```

### 2.1 Два режима одновременно

`MenuBarExtra` и `WindowGroup` живут в одном приложении и делят единый `AppState` (`@Observable`). Переключение между ними не теряет ни контекста беседы, ни незавершённого стриминга.

### 2.2 Агентный цикл

Пользовательское сообщение → запрос к провайдеру → стриминг токенов → при наличии `tool_calls` цикл прерывается, вызовы проходят через слой безопасности, результаты возвращаются в историю, цикл повторяется до ответа без вызовов.

Ограничение глубины цикла — защита от зацикливания локальных моделей.

## 4. LLM-слой

### 4.1 Протокол

```swift
protocol LLMProvider {
    var identifier: String { get }
    func availableModels() async throws -> [ModelInfo]
    func stream(_ request: ChatRequest) -> AsyncThrowingStream<StreamEvent, Error>
}
```

`StreamEvent` — токен текста, начало/завершение вызова инструмента, финализация, ошибка.

### 4.2 Реализации

- **LM Studio** — OpenAI-совместимый эндпоинт, порт 1234 по умолчанию.
- **Ollama** — нативный API, порт 11434 по умолчанию.

Автоопределение по порту при старте; ручной выбор провайдера и адреса в настройках перекрывает автодетект.

### 4.3 Function calling

Нативный OpenAI-совместимый tool calling. Схемы инструментов формируются из реестра. Модели, не поддерживающие нативные вызовы, работают в режиме чата без инструментов — без текстовых фолбэк-протоколов.

## 5. Инструменты

### 5.1 Протокол

```swift
protocol Tool {

    static var parameterSchema: JSONSchema { get }
```

### 5.2 Текущий набор (v0.2.4)

| Инструмент | Базовый уровень |
|---|---|

## 6. Модель безопасности (Rev 3)

### 6.1 Уровни риска

```swift
enum RiskLevel: Int, Comparable {
    case safe       // выполняется без подтверждения
    case caution    // подтверждение, допустима сессионная память
    case dangerous  // подтверждение всегда, память не применяется
}
```

**Определение уровня:** статичный базовый уровень объявляется инструментом; конкретный вызов может быть **повышен** на основании аргументов. Понижение невозможно ни при каких условиях.

Примеры повышения:
- `write_file` вне `allowed_dirs` → `dangerous`
- `delete_file` по пути с wildcard или на директорию → `dangerous`
- shell-команда в режиме `shell` (`/bin/zsh -c`) → всегда `dangerous`, независимо от содержимого (v0.4)

### 6.2 Подтверждение

Карточка Approve/Reject в ленте чата, визуально различающаяся по уровню: цвет рамки и заголовка, для `dangerous` — аргументы всегда развёрнуты, без сворачивания.

**Сессионная память** — только для `caution`. Пользователь может отметить «не спрашивать в этой сессии» — правило действует на пару (инструмент, уровень) до перезапуска приложения. Для `dangerous` опция недоступна: каждое обращение требует отдельного подтверждения. Это сознательное решение — иначе одно рассеянное нажатие открывает инструменту доступ на всю сессию.

### 6.3 Правила allow/block

Схема закладывается сразу на четыре измерения, принуждение вводится поэтапно:

| Измерение | Что описывает | Принуждение с |
|---|---|---|
| `path` | пути и глобы файловой системы | **v0.3** |
| `command` | regex-паттерны shell-команд | v0.4 |
| `application` | bundle ID целевых приложений | v0.5 |
| `host` | сетевые хосты | best effort, без гарантий |

```swift
@Model final class SecurityRule {
    var dimension: RuleDimension   // path | command | application | host
    var pattern: String
    var action: RuleAction         // allow | block
    var isEnabled: Bool
    var order: Int
    var isBuiltIn: Bool
}
```

**Порядок разрешения:** block имеет приоритет над allow. При отсутствии совпадений — поведение по умолчанию для уровня риска.

**Про сетевые хосты — честно.** Статический анализ аргументов не может определить, куда пойдёт `npm install`, `git pull` или произвольный скрипт. Проверяются только явные URL в аргументах. В UI это измерение помечается как неполное, чтобы не создавать ложного чувства защиты. Настоящее ограничение сети потребовало бы прокси или sandbox-профиля — вне текущего scope.

### 6.4 Sandbox-режим

**Не реализуется.** Списки правил — единственный механизм ограничения. Отдельный режим со своей семантикой создавал бы вторую, конкурирующую модель разрешений, которую пришлось бы держать согласованной с первой.

### 6.5 Журнал аудита

Каждый вызов инструмента фиксируется независимо от исхода:

```swift
@Model final class AuditEntry {
    var timestamp: Date
    var toolName: String
    var argumentsJSON: String
    var riskLevel: RiskLevel
    var decision: Decision        // approved | rejected | auto | blocked
    var outcome: Outcome          // success | failure | cancelled
    var resultSummary: String
    var conversationID: UUID?
}
```

Хранение — SwiftData. Просмотр — отдельное окно с фильтрами по дате, инструменту и уровню. Экспорт — JSONL-файл на диск.

## 7. Хранилище и настройки

- **SwiftData** — беседы, сообщения, вызовы инструментов, действия буфера, правила, аудит.

## 8. Clipboard Actions

Модуль применения LLM-действий к содержимому буфера обмена. Реализован в v0.2, тег `v0.2.4`.

- `ClipboardAction` в SwiftData, сидинг набора действий по умолчанию при первом запуске
- Пайплайн: буфер → промпт действия → LLM → буфер
- Триггер из menu bar и по глобальному хоткею `⌘⇧Space` с быстрым пикером
- Автовставка через `CGEvent` после проверки разрешения Accessibility
- Полноценный CRUD-редактор с изменением порядка и сбросом к дефолтам

## 9. Системная интеграция (Rev 3, планируется)

### 9.1 Shell / Terminal (v0.4)

Выполнение команд через `Process` с потоковым выводом stdout/stderr в ленту чата, таймаутами, отменой и явной рабочей директорией.

**Два режима запуска**, объявляемых параметром вызова:

| Режим | Реализация | Уровень риска |
|---|---|---|
| `direct` | `executableURL` + `arguments` | базовый, повышение по аргументам |
| `shell` | `/bin/zsh -c "строка"` | **всегда `dangerous`** |

Режим `shell` даёт пайпы, подстановки и `&&` — вместе со всем, чего модель не имела в виду. Поэтому цена выбора не зависит от самооценки модели: выбор режима остаётся за ней, уровень риска выводится автоматически.

Отдельный инструмент «открыть в Terminal.app» — для интерактивных команд, вывод которых ассистент не должен перехватывать.

### 9.2 Apple Events / AppleScript (v0.5)

Выполнение через `NSAppleScript` / `osascript`, плюс готовые рецепты для Finder, Mail, Calendar, Music, Safari/Chrome, Notes, Reminders.

**Ограничение, заложенное заранее:** Apple Events требуют TCC-разрешения на автоматизацию (`NSAppleEventsUsageDescription` + энтайтлмент `com.apple.security.automation.apple-events`), выдаваемого отдельно на каждую пару «наше приложение → целевое приложение». При ad-hoc подписи идентичность бандла меняется на каждой пересборке, поэтому в разработке разрешения будут слетать постоянно — умноженно на количество целевых приложений. То же, что уже наблюдалось с Accessibility в v0.2, только шире.

### 9.3 Нативные API (v0.6)

То, для чего AppleScript избыточен: `NSWorkspace` (запуск приложений, открытие файлов и URL), системная информация (батарея, диски, сеть, память), уведомления, громкость и яркость, управление окнами через Accessibility.

## 11. Нефункциональные требования

- Первый токен ответа — не позднее 2 с после отправки при загруженной модели
- Интерфейс не блокируется во время стриминга и выполнения инструментов
- Отмена любой длительной операции доступна в любой момент
- Приложение работает при полностью отключённой сети (кроме обращений к `localhost`)
- Нет исходящего трафика за пределы `localhost` ни при каких условиях

## 12. Распространение

Ad-hoc подпись (`codesign --sign -`), DMG с drag-to-install, публикация через `gh` CLI. В README — инструкция обхода Gatekeeper (правый клик → «Открыть», либо `xattr -cr`). Переход на полную нотаризацию выполняется заменой `--sign -` на Developer ID и добавлением шагов `notarytool` / `stapler`, без изменений в коде.
